# GLAZOV.M.TRANSLATE — паспорт проекта (PROJECT.md)

## Продукт-цель

- **Каким должен стать:** библиотека .NET, дающая программам владельца единый строго типизированный интерфейс ко всем переводчикам — Google, Microsoft, Bing, Yandex, Baidu и облачным API Google Cloud и Yandex Cloud — плюс единая лингвистическая система (язык, культура, регион, письменность и их коды).
- **Для кого:** собственные программы владельца; вместо отдельных клиентов к каждому переводчику и вместо строк-кодов языков.
- **Успех — это:** любой переводчик подключается за реализацию интерфейсов возможностей, не затрагивая домен; язык одного провайдера переводится в язык другого через общий домен; сборка и тесты проходят без ключей и сети (живые проверки пропускаются).
- **Сознательно НЕ входит:** собственный движок перевода; пользовательский интерфейс; зависимость домена от какого-либо провайдера или внешнего стандарта.

**Состояние:** IMPLEMENTATION (с 2026-10-01; присвоено при переезде в GES по состоянию кода — подтвердить владельцу)

## Что это

Многопроектное решение .NET 10. `Abstractions` — контракты и базовые типы; `Domain` — лингвистическая система с неизменяемыми реестрами (языки, культуры, регионы, письменности); `Providers.Common` — общая основа провайдеров; восемь провайдеров — отдельные проекты со своими тестами. Таблицы языков создают три генератора в `tools/`.

## Стек

- .NET 10 (`net10.0`), C#
- Сторонних NuGet-пакетов в библиотечных проектах нет — только BCL
- Тесты — xUnit; решение — `.slnx`

## Жёсткие ограничения (нарушать нельзя)

- Архитектура: Abstractions → Domain → Providers.Common → Providers.* — см. `docs/ARCHITECTURE.md`; провайдеры не зависят друг от друга.
- INV-001: домен не зависит от провайдеров; идентификаторы провайдера остаются внутри провайдера.
- INV-002: все доменные объекты и коллекции неизменяемы и потокобезопасны.
- INV-003: каждый идентификатор и каждый код — объект-значение; код не представляется голой строкой.
- INV-004: объект не может существовать в невалидном состоянии — проверка в конструкторе.
- INV-005: полный XML-документ у каждого публичного, защищённого и внутреннего API.
- INV-006: развитие малыми проверяемыми шагами, крупных переписываний нет; обратная совместимость сохраняется, где это практично.
- Полный авторский свод правил — `docs/Правила автора/Constitution.md`; он описывает код, а не работу, и применяется как требования к реализации.
