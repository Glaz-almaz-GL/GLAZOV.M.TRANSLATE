# VisualReferences

**Как продукт должен выглядеть.** Не реализация, а замысел.

## Что сюда класть

- Прототипы экранов и макеты
- Скриншоты целевого состояния — того, к чему идём
- Примеры отдельных экранов, блоков, компонентов
- Референсы: чужие интерфейсы, на которые ориентируемся, с пометкой, что именно в них взято за образец
- Схемы и наброски компоновки

Формат любой — `.html`, `.png`, `.fig`, `.pdf`, наброски на бумаге, сфотографированные телефоном. Требование одно: **по материалу должно быть понятно, что именно он показывает**. Файл `screen3.png` без пояснения бесполезен через полгода.

## Что сюда не класть

- Рабочие ассеты продукта (иконки, шрифты, изображения, которые реально используются) — им место в самом проекте.
- Скриншоты багов — они относятся к задаче, а не к замыслу.

## Зачем это нужно

Чтобы визуальный замысел пережил автора и время. Разница между «собрать экран заново по описанию» и «собрать экран заново по картинке этого экрана» — это разница между переизобретением и восстановлением.

Для сайтов эта папка важнее, чем для чего-либо ещё: сайт **и есть** свой внешний вид, и без сохранённых прототипов редизайн не с чем сравнивать.
